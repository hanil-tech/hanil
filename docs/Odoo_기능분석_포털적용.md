# Odoo 기능 분석 → 한일 포털 적용안

> 목적: Odoo(odoo.com)의 업무 앱 기능을 정리하고, 한일특장 포털에 없거나 약한 기능을 골라 우선순위와 만드는 방법을 정한다.
> 조사일: 2026-11-14 · 대상: `https://www.odoo.com/ko_KR` (전체 앱 목록 + 앱 25개 소개 페이지)

---

## 0. 조사 방법과 한계

| 단계 | 결과 |
|---|---|
| REA 브라우저 분석 (`capture_web_screenshot`, `inspect_web_page`) | ❌ Odoo 사이트가 자동 브라우저(HeadlessChrome)를 **`403 Forbidden — Request forbidden by administrative rules`** 로 막음. 차단을 우회하지 않았다. |
| 일반 웹 요청으로 공개 페이지 읽기 | ✔ 전체 앱 목록(49개 앱·8개 분야)과 앱 25개의 기능 설명을 읽음 (요청 사이 2초 간격) |
| 포털 현재 기능 | `server.js` 에서 본 `require('./…')` 조각 이름과 지금까지 작업으로 추정. **실제 화면과 다를 수 있으니 확인 필요** (6장 ①) |

- Odoo 의 화면이나 코드를 복제하지 않는다. **기능 아이디어만** 가져와서 포털 구조(Node.js + 조각 `require('./x')(app, ctx)`)에 맞게 새로 만든다.
- Odoo Community 판은 LGPL 오픈소스라 공개 문서와 데이터 구조를 참고하는 데 문제가 없다. Enterprise 전용 기능(스튜디오, 서명, 문서 등)은 설명만 참고한다.

## 4. ① 수주 건별 제작 관리 — 설계

Odoo 의 제조(MRP)·프로젝트·품질 기능을 **특장차 주문 생산**에 맞게 하나로 줄인 것.

### 4.1 화면
1. **제작 현황판 (칸반)**: 열 = 공정 단계. 카드 = 수주 1건(고객 · 차종 · 차대번호 · 납기 · 진행률). 납기가 가까우면 빨간색.
   - 기본 단계: `수주` → `설계/도면` → `자재` → `제관/용접` → `도장` → `조립/전장` → `검사` → `출고`
2. **간트 일정**: 수주별 공정 기간을 막대로 표시하고 끌어서 조정. 작업장별 겹침 경고 (Odoo 「충돌 방지」).
3. **수주 상세**: 사양 · 도면(기존 `drawings` 연결, 판 번호) · 자재명세(BOM) · 공정별 담당·시작/완료 · 검사 결과 · 사진 · 원가(기존 `cost` 연결) · 대화 기록.
4. **작업자 태블릿 화면**: 오늘 내 공정 목록 → 「시작」 「완료」 「문제 보고」 단추만 있는 큰 버튼 화면 (Odoo 「작업 공정 앱」·「종이 없는 회사」).

### 4.2 데이터 (포털 DB 표)
| 표 | 주요 칸 |
|---|---|
| `mfg_orders` | id · 수주번호 · 거래처(`partner`) · 견적(`quote`) 연결 · 차종 · 차대번호 · 사양(JSON) · 납기 · 상태 · 담당자 |
| `mfg_steps` | id · order_id · 단계 · 작업장 · 담당 · 예정 시작/끝 · 실제 시작/끝 · 상태 · 메모 |
| `mfg_bom` | order_id · 품목 · 수량 · 단위 · 재고 연결 · 발주 연결 |
| `mfg_photos` | order_id · step_id · 파일 · 찍은 사람 · 시각 |

### 4.3 다른 기능과 잇기
- 견적 → 「수주로 만들기」 단추 하나로 `mfg_orders` 생성 (Odoo 「클릭 두 번으로 견적서」).
- 단계 완료 → 다음 단계 담당자에게 **NOPS 알림** (포털 `nopsPush`).
- `검사` 단계 → ② 품질 검사 양식이 자동으로 열림.
- `출고` → 고객 인수 서명(④) · 출고 라벨(`labels`) · A/S 이력(②)에 차대번호 등록.

## 5. ② 품질 검사 · A/S 접수 — 설계 요약

### 품질 (Odoo 「품질」 참고)
- **검사 양식**: 차종별 체크리스트(항목 · 기준 · 합격/불합격 · 사진 · 측정값). 관리자가 화면에서 항목 편집.
- **부적합(품질 경고)**: 불합격 항목 → 칸반(접수 → 원인 분석 → 시정 → 확인 → 종료), 중요도 별 1~3개.
- **통계**: 차종·공정·항목별 불합격 횟수 (가장 자주 나오는 결함).

### A/S 접수 (Odoo 「헬프데스크」 참고)
- **접수**: 고객 전화·팩스·웹 양식 → 차대번호로 차량·출고일·보증 기간 자동 조회.
  - 팩스로 온 A/S 요청은 **팩스 AI 판독 결과로 자동 접수 초안**을 만든다 (오늘 만든 자동 판독과 연결).
- **처리 기한(SLA)**: 접수 후 N시간 안에 연락, N일 안에 처리. 넘기면 빨간색과 알림.
- **이력**: 차대번호별 A/S 기록 → 같은 결함이 반복되면 ② 품질 부적합으로 올리는 단추.

## 6. 진행 제안

1. **포털 현재 기능 확인** (반나절): 2장의 "포털에 있는 것"이 추정이므로, 포털 메뉴 화면 캡처나 `server.js` 의 조각 목록으로 확인한다.
2. **①의 최소판** (1~2주): 제작 현황판 + 수주 상세 + 단계 완료 알림. 간트·태블릿 화면은 다음 단계에서.
3. **② 품질·A/S** (각 1주): ①의 검사 단계와 차대번호에 붙인다.
4. **③ 이후**: 사용해 보며 필요한 순서로 진행한다.

- 포털 원본을 다른 곳에서 관리하므로, 이 저장소에서는 팩스 때처럼 **포털 조각(`require('./x')(app, ctx)`) + 설치 안내 + 가짜 포털 점검** 형태로 만들어 넘기는 방식을 권한다.
- 각 기능은 포털의 기존 로그인(`req.session.user`), 관리자 판단(`freshRole`), NOPS 알림(`nopsPush`), DB(`DB.run`)를 그대로 쓴다.
