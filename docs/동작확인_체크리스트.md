# Windows 실제 동작 확인 체크리스트

스케줄 판정 로직은 단위 테스트로 검증되어 있지만, Windows 고유 동작(서비스 등록,
전원 차단, 트레이 아이콘, 세션 간 프로세스 실행)은 실제 Windows PC 에서 한 번
확인해야 합니다. 아래 순서대로 점검하시면 됩니다.

> **먼저 시험용 PC 나 가상 머신에서 확인하세요.** 전원 차단을 실제로 실행하는
> 프로그램입니다. 업무 PC 에 바로 넣지 마십시오.

## 1단계 — 설치와 서비스 기동

- [ ] **설치 파일 하나만** 복사해도 설치가 된다 (다른 파일 없이)
- [ ] 메신저로 보낸 뒤 받은 파일로도 설치가 된다 (파일 이름이 깨지지 않는다)
- [ ] 차단된 파일이면 [속성] → [차단 해제] 로 풀린다
- [ ] `TimeGuard-Setup.exe` 아이콘이 파란 시계 모양으로 보인다
- [ ] 더블클릭하면 관리자 권한을 물어본다
- [ ] **검은 명령 창이 아니라 Windows 창**이 뜬다
- [ ] 단추와 진행 막대가 요즘 Windows 모양이다 (각진 회색이 아니다)
- [ ] 한글이 깨지지 않고, 고해상도 화면에서도 글자가 또렷하다
- [ ] [설치] 를 누르면 진행 상황이 한 줄씩 올라간다
- [ ] 설치 중에는 창을 닫을 수 없다 (안내 창이 뜬다)
- [ ] 설치 마지막 화면에 PC 이름과 확인 문자(8자리)가 나온다
- [ ] [PC 이름·확인 문자 복사] 를 누르면 메모장에 붙여넣기가 된다
- [ ] `sc query HanilTimeGuard` 결과가 `RUNNING`
- [ ] `C:\ProgramData\HanilTimeGuard\config.json` 이 생성되었다
- [ ] 일반 사용자 계정으로 로그인해 `config.json` 을 수정하면 **거부된다**
- [ ] `timeguard.log` 에 "서비스를 시작했습니다" 가 남았다

## 1-1단계 — 설치 오류가 났을 때

- [ ] 오류 창에 무엇이 잘못됐는지 한글로 나온다
- [ ] 오류 기록 파일 위치가 창에 적혀 있다
- [ ] 그 파일을 열면 Windows 버전과 자세한 원인이 들어 있다

## 2단계 — 관리자 도구

- [ ] `TimeGuard.Admin.exe` 실행 시 한글이 깨지지 않는다
- [ ] 비밀번호를 설정할 수 있다 (`10`번)
- [ ] 비밀번호 설정 전에는 감시를 켤 수 없다
- [ ] 허용 시간대를 저장하면 `config.json` 에 반영된다
- [ ] 틀린 비밀번호로는 설정이 변경되지 않는다
- [ ] `TimeGuard.Admin.exe status` 가 현재 상태를 출력한다

## 3단계 — 알림 (조치는 '화면 잠금'으로 먼저 시험)

먼저 조치를 **화면 잠금**(`4`번 → `3`)으로 바꾸고 시험하면 안전합니다.

- [ ] 트레이에 아이콘이 보인다
- [ ] 아이콘에 마우스를 올리면 남은 시간이 보인다
- [ ] 아이콘을 클릭하면 안내 창이 뜬다
- [ ] 종료 10분 전 알림이 뜬다
- [ ] 마지막 60초에 카운트다운 창이 화면 가운데 뜬다
- [ ] 카운트다운 창이 **다른 창 위에** 계속 보인다
- [ ] 카운트다운 창을 Alt+F4 로 닫아도 다시 나타난다 (또는 닫히지 않는다)
- [ ] 카운트다운 창이 뜬 동안에도 다른 프로그램에 **계속 입력할 수 있다** (포커스를 뺏지 않음)
- [ ] 한글이 깨지지 않고 표시된다

시험을 빨리 하려면 허용 시간대를 지금 시각 기준 몇 분 뒤로 끝나게 잡으세요.
예를 들어 지금이 14:20 이면 `09:00-14:23` 으로 설정합니다.

## 4단계 — 우회 시도 (중요)

- [ ] 작업 관리자에서 `TimeGuard.Agent.exe` 를 강제 종료해도 **조치는 그대로 실행된다**
- [ ] 강제 종료한 에이전트가 30초 안에 **다시 뜬다**
- [ ] 일반 사용자 계정에서 작업 관리자로 서비스를 중지할 수 **없다**
- [ ] 일반 사용자가 `config.json` 을 고쳐 시간을 늘릴 수 **없다**

## 5단계 — 전원 차단 (시험용 PC 에서만)

- [ ] 조치를 `전원 차단`으로 바꾸고, 허용 시간이 끝나면 실제로 PC 가 꺼진다
- [ ] 꺼지기 전에 `timeguard.log` 에 조치 기록이 남는다

## 6단계 — 경계 상황

- [ ] 허용 시간대 **밖에서** PC 를 켜면 120초 유예 후 조치된다
- [ ] 일시 중지(`7`번) 중에는 시간이 지나도 꺼지지 않는다
- [ ] 임시 연장(`6`번)을 주면 그만큼 더 쓸 수 있다
- [ ] 연장 시간이 끝나면 다시 차단된다
- [ ] 제외 계정으로 로그인하면 제한받지 않는다
- [ ] 야간 구간(`22:00-06:00`)이 자정을 넘겨서도 유지된다
- [ ] PC 시간을 바꿔도 서비스가 다음 초에 올바르게 판정한다
- [ ] 절전/최대 절전에서 깨어난 뒤에도 올바르게 판정한다

## 7단계 — 재부팅

- [ ] 재부팅 후 서비스가 자동으로 시작된다
- [ ] 로그온하면 트레이 아이콘이 자동으로 뜬다
- [ ] `services.msc` 에서 서비스를 강제 종료해도 5초 뒤 자동 복구된다

# 관리 서버 확인 체크리스트

서버 자체는 Linux 에서 실제로 띄워 API 와 화면 전 과정을 확인했고 통합 테스트 55개가
이를 지키고 있습니다. 아래는 **Windows 서비스로 설치했을 때**와 **직원 PC 와 실제로
연결했을 때** 확인해야 할 부분입니다.

## 8단계 — 서버 설치

- [ ] `TimeGuard-Server-Setup.exe` 아이콘이 초록 시계 모양으로 보인다
- [ ] 더블클릭하면 관리자 권한을 물어보고 Windows 창이 뜬다
- [ ] [설치] → 암호화 체크와 포트 칸이 보인다
- [ ] [설치 시작] 이 오류 없이 끝난다
- [ ] 설치 마지막 화면에 접속 주소와 임시 비밀번호가 나온다
- [ ] [주소·비밀번호 복사] 가 동작한다
- [ ] [관리 화면 열기] 를 누르면 브라우저가 그 주소로 열린다
- [ ] `sc query HanilTimeGuardServer` 결과가 `RUNNING`
- [ ] 같은 PC 에서 `http://localhost:8080` 이 열린다
- [ ] **다른 PC 에서** `http://<서버IP>:8080` 이 열린다 (방화벽 확인)
- [ ] `최초설정정보.txt` 의 비밀번호로 로그인된다
- [ ] 일반 사용자 계정으로 `C:\ProgramData\HanilTimeGuardServer` 에 접근하면 거부된다
- [ ] 비밀번호를 바꾼 뒤 이전 비밀번호로는 로그인되지 않는다
- [ ] 서버 PC 를 재부팅해도 서비스가 자동으로 시작된다

## 9단계 — 직원 PC 연결

- [ ] 설치만 하면 서버 [새 PC 승인] 에 그 PC 가 나타난다 (등록 키 입력 없음)
- [ ] 메뉴 [새 PC 승인] 옆 숫자가 기다리는 대수와 같다
- [ ] 승인 화면의 확인 문자가 설치 화면에 찍힌 값과 같다
- [ ] **승인 전에는** 그 PC 에 아무 시간표도 내려가지 않는다
- [ ] [승인] 을 누르면 1분 안에 그 PC 에 시간표가 적용된다
- [ ] 승인된 PC 가 [PC 목록] 으로 옮겨 간다
- [ ] [거절] 한 PC 는 계속 정책을 받지 못한다
- [ ] [모두 승인] 이 여러 대를 한 번에 처리한다
- [ ] `config.json` 이 서버 정책 내용으로 바뀌어 있다
- [ ] [PC 상세] 에서 전용 시간표를 저장하면 1분 안에 그 PC 에 반영된다
- [ ] [PC 상세] 에서 즉시 연장을 주면 직원 PC 에 반영된다

## 10단계 — 우회 시도 (중요)

- [ ] 서버 모드에서 `TimeGuard.Admin.exe` 메뉴로 시간표를 바꾸려 하면 **거부된다**
- [ ] `config.json` 을 관리자 권한으로 고쳐도 **서비스가 서버 정책으로 되돌린다**
- [ ] 랜선을 뽑아도 **시간이 되면 그대로 꺼진다**
- [ ] 랜선을 뽑은 PC 가 서버 화면에 **"연결 끊김" 으로 표시된다**
- [ ] 서버를 꺼도 직원 PC 의 제한이 유지된다
- [ ] 직원 PC 를 재부팅해도 (서버 연결 전에도) 제한이 바로 적용된다
      → `policy-cache.json` 이 있는지 확인
- [ ] 일반 사용자 계정으로 `net stop HanilTimeGuard` 가 **거부된다**

## 11단계 — 연장 요청

- [ ] 트레이 아이콘 오른쪽 클릭에 [사용 시간 연장 요청] 이 보인다
- [ ] 요청 창의 한글이 깨지지 않는다
- [ ] 사유를 비우고 보내면 입력하라고 알려 준다
- [ ] 요청을 보내면 서버 [연장 요청] 에 뜬다
- [ ] 승인하면 직원 PC 에 알림이 뜬다
- [ ] 승인한 만큼 실제로 더 쓸 수 있다
- [ ] 거절하면 거절 알림과 사유가 직원 PC 에 뜬다
- [ ] 대기 중 요청이 3건 쌓이면 더 못 올린다

## 12단계 — 여러 대 운영

- [ ] PC 2대 이상을 등록해도 각각 다른 시간표를 줄 수 있다
- [ ] 기본 시간표를 바꾸면 전용 시간표를 쓰지 않는 PC 들에만 반영된다
- [ ] 한 PC 의 연장이 다른 PC 에 영향을 주지 않는다
- [ ] 같은 PC 에 클라이언트를 재설치해도 목록에 중복으로 생기지 않는다

# 보안 강화 기능 확인

## 13단계 — 사내망 자동 검색

- [ ] 서버를 켠 상태에서 직원 PC 에서 `TimeGuard.Admin.exe discover` 가 서버를 찾는다
- [ ] 찾은 주소와 서버 PC 이름이 맞다
- [ ] `TimeGuard-Setup.exe` 더블클릭만으로 서버를 찾아 자기를 알린다
- [ ] 서버를 끄면 찾지 못한다고 안내한다
- [ ] 서버 방화벽에서 UDP 8765 가 열려 있다

## 14단계 — 관리 화면 접근 제한

- [ ] 서버 [설정] 에서 [지금 이 PC 에서만 열리도록 설정] 이 동작한다
- [ ] 제한을 건 뒤 **직원 PC 브라우저에서 관리 화면이 열리지 않는다**
- [ ] 제한을 건 뒤에도 직원 PC 의 시간 제한은 정상 동작한다
- [ ] 서버 PC 에서 `localhost` 로는 여전히 접속된다 (잠기지 않는 안전장치)
- [ ] 잘못된 주소를 넣으면 저장되지 않고 오류를 알려 준다

## 15단계 — 로그인 대입 차단

- [ ] 비밀번호를 5번 틀리면 잠긴다
- [ ] 잠긴 동안에는 **올바른 비밀번호로도** 로그인되지 않는다
- [ ] 15분 뒤에 다시 로그인할 수 있다
- [ ] 다른 PC 에서는 영향 없이 로그인된다

## 16단계 — 통신 암호화

- [ ] 설치 후 주소가 `https://` 로 시작한다
- [ ] 서버 PC 브라우저에서 인증서 경고가 뜨지 않는다
- [ ] 다른 PC 에서 경고가 뜨면 `서버인증서.cer` 설치 후 사라진다
- [ ] 직원 PC 가 HTTPS 로 정상 등록된다
- [ ] `server.json` 에 인증서 지문이 기록되어 있다
- [ ] 서버를 다시 설치해도 (기존 인증서 재사용) 직원 PC 가 계속 동작한다

## 17단계 — 계정 잠금 (시험용 PC 에서만)

> **반드시 시험용 PC 에서 먼저 확인하십시오.** 잘못 쓰면 직원이 로그인하지 못합니다.

- [ ] 조치를 [계정 잠금] 으로 바꾸면 경고와 함께 확인을 묻는다
- [ ] 시간이 지나면 로그오프되고 **다시 로그인할 수 없다**
- [ ] 직원이 스스로 풀 수 없다
- [ ] **허용 시간이 되면 자동으로 풀려 로그인된다** (가장 중요)
- [ ] 서비스를 껐다 켜도 (허용 시간이면) 자동으로 풀린다
- [ ] 관리자 권한 계정에는 적용되지 않는다 (기록에 그 이유가 남는다)
- [ ] 제한 제외 계정에는 적용되지 않는다
- [ ] `TimeGuard.Admin.exe unlock-accounts` 로 비상 복구가 된다
- [ ] 프로그램을 제거하면 잠긴 계정이 풀린다

## 18단계 — 변조 방지

- [ ] 일반 사용자가 `net stop HanilTimeGuard` 를 할 수 없다
- [ ] **관리자 계정으로도** `net stop HanilTimeGuard` 가 거부된다 (보호 설정)
- [ ] 일반 사용자가 `C:\Program Files\HanilTimeGuard` 의 파일을 지울 수 없다
- [ ] `TimeGuard-Setup.exe` 의 [제거] 는 보호를 풀고 정상적으로 제거한다
- [ ] 제거하면 잠겨 있던 Windows 계정이 풀리고 원격 접속 설정이 되돌아간다
- [ ] 서비스를 강제로 멈추면 서버 화면에 "연결 끊김" 으로 뜬다

## 19단계 — 껐다 켜기 반복

- [ ] 허용 시간 밖에서 처음 켜면 약 120초 뒤 조치된다
- [ ] 다시 켜면 유예가 절반으로 줄어든다 (약 60초)
- [ ] 계속 반복하면 최소 15초까지 줄어들고 그 아래로는 내려가지 않는다
- [ ] 서버 기록에 몇 번째 시도인지 남는다
- [ ] 허용 시간이 되면 기록이 지워져 다음 날 다시 120초부터 시작한다

## 20단계 — 원격 접속 차단 (시험용 PC 에서만)

> 원격으로 관리하시는 PC 라면 이 기능을 켜기 전에 반드시 시험해 보십시오.

- [ ] 서버 [기본 시간표] → 원격 접속 을 "차단 중에는 막음" 으로 바꾼다
- [ ] 허용 시간 중에는 원격 데스크톱 접속이 정상 동작한다
- [ ] 허용 시간이 지나면 **원격 데스크톱 접속이 거부된다**
- [ ] 접속해 있던 원격 세션이 끊긴다
- [ ] **허용 시간이 되면 원격 접속이 다시 된다** (가장 중요)
- [ ] 서비스를 껐다 켜도 (허용 시간이면) 원격 접속이 복구된다
- [ ] 원래 원격 접속을 꺼 두었던 PC 는 허용 시간이 되어도 켜지지 않는다
- [ ] 설정을 "막지 않음" 으로 되돌리면 차단이 풀린다

## 21단계 — 연장 요청 사유

- [ ] 요청 창에 사유 입력란이 보인다
- [ ] 사유를 비우고 보내면 입력하라고 알려 준다
- [ ] 너무 짧게 적으면 자세히 적으라고 알려 준다
- [ ] 보낸 사유가 서버 [연장 요청] 화면에 그대로 보인다
- [ ] 요청자 계정 이름과 요청 시각도 함께 보인다
- [ ] 거절할 때 적은 사유가 직원 PC 알림에 보인다

## 22단계 — 원격 제어 프로그램 차단 (시험용 PC 에서만)

> 시험용 PC 에 팀뷰어나 AnyDesk 를 설치해 두고 확인하십시오.

- [ ] 서버 [기본 시간표] → 원격 제어 프로그램 을 "차단 중에는 막음" 으로 바꾼다
- [ ] 허용 시간 중에는 팀뷰어가 정상 동작한다
- [ ] 허용 시간이 지나면 **팀뷰어 프로그램이 종료된다**
- [ ] **팀뷰어 서비스도 멈춘다** (작업 관리자 → 서비스 탭에서 확인)
- [ ] 밖에서 팀뷰어로 접속을 시도하면 연결되지 않는다
- [ ] 팀뷰어를 다시 실행해도 몇 초 안에 다시 종료된다
- [ ] 허용 시간이 되면 팀뷰어를 다시 쓸 수 있다
- [ ] 추가로 적은 프로그램 이름도 똑같이 막힌다
- [ ] 실행 파일 이름을 바꾸면 막히지 않는다 (알려진 한계 — 확인만)

## 23단계 — 기록

- [ ] 원격 제어 프로그램이 종료될 때 서버 [기록] 에 `보안` 항목으로 남는다
- [ ] [PC 목록] 화면 위쪽에 보안 기록 건수가 빨갛게 뜬다
- [ ] [기록] 에서 구분을 `보안` 으로 골라 그것만 볼 수 있다
- [ ] 어느 PC, 언제, 어떤 프로그램인지 내용에 들어 있다
- [ ] 막지 못한 경우에도 기록이 남는다 (권한 부족 등)
- [ ] 같은 프로그램이 반복 발견되어도 기록이 도배되지 않는다
- [ ] 직원 PC 의 `timeguard.log` 에도 같은 내용이 남는다
- [ ] 서버 연결을 끊고 기록이 쌓인 뒤 다시 연결하면 밀린 기록이 올라간다
- [ ] 원격 데스크톱 차단·해제도 기록에 남는다
- [ ] 계정 잠금·해제도 기록에 남는다

## 24단계 — 관리자 권한 감지

- [ ] 관리자 권한 계정으로 로그인한 PC 가 [PC 목록] 에 **"관리자 권한"** 으로 표시된다
- [ ] 화면 위쪽에 "N 대의 PC 에서..." 경고가 뜬다
- [ ] PC 상세 화면에도 경고가 나온다
- [ ] 처음 발견될 때 [기록] 에 `보안` 항목으로 남는다
- [ ] 매 연락마다 반복 기록되지 않는다
- [ ] 계정 권한을 낮추면 1분 안에 표시가 사라진다
- [ ] 일반 사용자 계정 PC 에는 표시가 없다

## 25단계 — 직원 계정 권한 낮추기

`직원계정_권한낮추기.md` 를 따라 해 보십시오.

- [ ] 2단계에서 만든 관리자 계정으로 **로그인이 된다** (가장 중요)
- [ ] 그 계정으로 관리자 권한 명령 프롬프트를 열 수 있다
- [ ] 직원 계정을 낮춘 뒤 `net localgroup Administrators` 에 직원 이름이 없다
- [ ] 직원 계정으로 `net stop HanilTimeGuard` 가 **거부된다**
- [ ] 직원 계정으로 `C:\Program Files\HanilTimeGuard` 의 파일을 지울 수 없다
- [ ] 직원이 평소 쓰는 업무 프로그램이 정상 동작한다
- [ ] 계정 잠금 조치가 이제 그 계정에 적용된다
