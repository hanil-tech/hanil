# 한일 TimeGuard

관리자가 정한 시간대를 벗어나면 직원 PC 를 안내 후 종료하는 Windows 프로그램입니다.
**중앙 관리 서버**에서 PC 별 시간표를 정하고, 직원이 올린 연장 요청을 승인합니다.

## 왜 서버가 필요한가

직원 PC 에만 설치하는 방식은 한 가지 약점이 있습니다. **직원이 관리자 비밀번호를 알아내면
자기 PC 에서 감시를 꺼 버릴 수 있습니다.** 비밀번호가 그 PC 에 저장되어 있고, 판단도 그 PC 가
하기 때문입니다.

서버를 두면 권한이 직원 PC 에서 사라집니다. 비밀번호를 알아내도 그 PC 에서는 바꿀 수 있는 게
없습니다. 그리고 누군가 서비스를 멈추거나 랜선을 뽑으면 **서버 화면에 "연결 끊김" 으로 남아
관리자가 알 수 있습니다.**

> 다만 직원 계정이 Windows 관리자 권한을 갖고 있으면 서비스를 멈출 방법은 여전히 있습니다.
> **직원 계정은 일반 사용자로 낮추는 것**을 함께 하셔야 효과가 제대로 납니다.

## 전체 구조

```
   ┌─────────────────────────────────────────┐
   │  관리 서버 (사무실 PC 한 대)              │
   │  TimeGuard.Server.exe                    │
   │                                          │
   │  · 웹 브라우저로 관리                     │
   │  · PC 별 시간표 지정                      │
   │  · 연장 요청 승인 / 거절                  │
   │  · 각 PC 상태와 기록 확인                 │
   └────────────────┬────────────────────────┘
                    │  사내망 (기본 60초마다)
        ┌───────────┼───────────┐
        ▼           ▼           ▼
   ┌─────────┐ ┌─────────┐ ┌─────────┐
   │ 직원PC 1 │ │ 직원PC 2 │ │ 직원PC 3 │
   │          │ │          │ │          │
   │ 서비스   │ │ 서비스   │ │ 서비스   │  ← 감시·전원 차단 (SYSTEM 권한)
   │ 에이전트 │ │ 에이전트 │ │ 에이전트 │  ← 경고·카운트다운·연장 요청
   └─────────┘ └─────────┘ └─────────┘
```

**연결이 끊겨도 제한은 유지됩니다.** 각 PC 는 마지막으로 받은 시간표를 파일로 보관해 두고
그대로 적용합니다. 랜선을 뽑거나 서버를 꺼서 제한을 피할 수 없습니다.

## 구성 프로그램

| 프로그램 | 설치 위치 | 역할 |
|---|---|---|
| `TimeGuard.Server.exe` | 관리 서버 PC | 웹 관리 화면, 시간표 배포, 연장 승인 |
| `TimeGuard.Service.exe` | 직원 PC (서비스) | 시간 감시, 전원 차단, 서버와 통신 |
| `TimeGuard.Agent.exe` | 직원 PC (사용자 세션) | 트레이 아이콘, 경고, 카운트다운, 연장 요청 |
| `TimeGuard.Admin.exe` | 직원 PC | 서버 등록, 상태 확인, 단독 모드 설정 |

### 왜 서비스와 에이전트로 나누었나

Windows 서비스는 세션 0 에 격리되어 있어 사용자 화면에 창을 띄울 수 없습니다.
그래서 **판정과 조치는 서비스**가, **화면 표시는 에이전트**가 맡습니다.

이 구조 덕분에 **사용자가 에이전트를 강제 종료해도 차단은 그대로 실행됩니다.** 경고만 못 볼
뿐입니다. 서비스가 30초마다 확인해 에이전트를 다시 띄우기도 합니다.

### 1단계 — 관리 서버

사무실 PC 한 대를 정해 `dist/TimeGuard-서버` 폴더를 복사한 뒤, 폴더 안의
**`TimeGuard서버-설치.exe` 를 더블클릭**합니다.

Windows 가 관리자 권한을 물어보면 [예], 메뉴에서 [1] 설치 를 누릅니다.
암호화 여부와 포트만 물어보고(둘 다 Enter 로 기본값), 나머지는 알아서 합니다.

- 프로그램 복사와 폴더 권한 설정
- 사내용 인증서 생성 (HTTPS)
- 방화벽 개방 — 사내망 프로필만
- 서비스 등록·보호·시작

끝나면 접속 주소와 임시 비밀번호를 화면에 보여 줍니다.

브라우저로 접속해 다음 순서로 진행하세요.

| 순서 | 화면 | 내용 |
|---|---|---|
| 1 | 로그인 | 아이디 `admin`, 임시 비밀번호 |
| 2 | 설정 | 관리자 비밀번호 변경 |
| 3 | 기본 시간표 | 예: 월~금 `09:00-18:00`, 토·일 `없음` |

### 2단계 — 직원 PC (더블클릭 한 번)

`dist/TimeGuard` 폴더를 복사한 뒤, 폴더 안의
**`TimeGuard-설치.exe` 를 더블클릭**합니다. [1] 설치 를 누르면 끝입니다.

**등록 키도, 서버 주소도 입력하지 않습니다.** 설치된 PC 가 사내망에서 서버를
찾아 스스로 자기를 알립니다.

여러 대를 자동으로 설치할 때만 명령줄을 씁니다.

```
TimeGuard-설치.exe /설치
```

### 3단계 — 서버에서 승인

새로 설치된 PC 는 서버의 **[새 PC 승인]** 화면에 나타납니다. 메뉴 옆 빨간 숫자가
기다리는 대수입니다.

| 보이는 것 | 쓰임 |
|---|---|
| PC 이름 · 로그인 사용자 | 어느 자리의 PC 인지 확인 |
| 확인 문자 (8자리) | 설치 화면에 찍힌 값과 같은지 대조 |
| 관리자 권한 표시 | 그 계정이 서비스를 멈출 수 있는지 |

[승인] 을 누르면 그때부터 시간표가 내려가고 **PC 목록**으로 옮겨 갑니다.
여러 대를 한꺼번에 승인하려면 [모두 승인] 을 누릅니다.

모르는 PC 는 [거절] 합니다. **승인 전에는 어떤 정책도 내려가지 않습니다.**

> .NET 설치가 필요 없습니다. 런타임이 함께 들어 있습니다.

#### 서버를 어떻게 찾나

직원 PC 가 사내망에 "관리 서버 계십니까" 하고 물으면 서버가 자기 주소를 알려 줍니다.
그래서 PC 마다 IP 를 받아 적어 넣지 않아도 됩니다.

찾지 못하면 `-Server` 로 주소를 직접 적으면 됩니다. 서버가 여러 대 발견되면
어느 것이 맞는지 물어봅니다.

## 시간이 다 됐을 때 무엇을 할까

| 조치 | 직원이 되돌릴 수 있나 | 설명 |
|---|---|---|
| **전원 차단** | 다시 켤 수는 있음 | 컴퓨터를 끕니다. 가장 확실합니다 |
| **계정 잠금** | **불가능** | 로그오프 후 Windows 로그인 자체가 막힙니다. 허용 시간이 되면 자동으로 풀립니다 |
| 로그오프 | 바로 다시 로그인 | 로그아웃만 합니다 |
| 화면 잠금 | 바로 풂 | **직원이 자기 비밀번호로 즉시 풉니다. 제한 효과가 거의 없습니다** |

**화면 잠금은 권하지 않습니다.** Windows 화면 잠금은 사용자가 자기 비밀번호를 넣으면
바로 풀리기 때문에 시간 제한의 의미가 없습니다.

**계정 잠금**은 Windows 계정을 사용 중지 상태로 만들어 로그인 자체를 막습니다.
직원이 스스로 풀 수 없고, 허용 시간이 되면 서비스가 자동으로 풀어 줍니다.
안전을 위해 다음과 같이 해 두었습니다.

- 관리자 권한을 가진 계정에는 적용되지 않습니다 (PC 를 되돌릴 방법이 사라지므로)
- 제한 제외 계정으로 등록한 계정에도 적용되지 않습니다
- 서비스가 다시 시작될 때 허용 시간이면 곧바로 풀어 줍니다
- 프로그램을 제거하면 잠긴 계정을 모두 풀고 나갑니다
- 비상시: `TimeGuard.Admin.exe unlock-accounts`

## 원격으로 들어오는 것도 막기

계정을 잠가도 그 PC 에 **다른 계정**이 있으면 그 계정으로 원격 데스크톱 접속해 쓸 수 있습니다.
서버 [기본 시간표] → **원격 접속** 을 "차단 중에는 막음" 으로 두면 이것까지 막힙니다.

- 허용 시간이 아니면 원격 데스크톱 접속이 거부됩니다
- 이미 접속해 있던 원격 세션도 끊깁니다
- 허용 시간이 되면 자동으로 원래대로 돌아갑니다
- 원래부터 원격 접속을 꺼 두었던 PC 는 건드리지 않습니다

기본값은 **꺼짐**입니다. 원격으로 일하시는 곳이 갑자기 막히면 곤란하므로,
필요한 곳에서만 켜시도록 했습니다.

### 팀뷰어 같은 원격 제어 프로그램

Windows 원격 데스크톱만 막으면 **팀뷰어, AnyDesk 같은 프로그램으로 들어올 수 있습니다.**
이런 프로그램은 서비스로 상주하는 경우가 많아, 로그아웃 상태나 로그인 화면에서도
접속을 받아 줍니다.

서버 [기본 시간표] → **원격 제어 프로그램**을 켜면 차단 중에 이런 프로그램을
프로그램과 서비스 양쪽 모두 멈춥니다. 기본으로 막는 것들입니다.

> TeamViewer · AnyDesk · RustDesk · Chrome 원격 데스크톱 · UltraVNC · TightVNC ·
> RealVNC · RemoteView · LogMeIn · Splashtop · Ammyy · Supremo · NetSupport ·
> Zoho Assist · GoToAssist

사내에서 따로 쓰는 도구가 있으면 실행 파일 이름을 적어 추가할 수 있습니다.

**한계도 알아 두십시오.** 실행 파일 이름을 바꿔 두면 이 목록으로는 잡히지 않습니다.
그래서 막는 것과 함께 **발견 사실을 반드시 기록에 남깁니다.** 막지 못한 경우에도
기록은 남습니다. 확실히 막으시려면 조치를 **전원 차단**으로 두시는 편이 낫습니다.
PC 가 꺼져 있으면 어떤 방법으로도 들어올 수 없습니다.

## 기록

원격으로 들어오려 한 시도는 `보안` 항목으로 남습니다.

- **PC 목록** 화면 위쪽에 최근 하루치 보안 기록 건수가 빨갛게 뜹니다
- **기록** 화면에서 `보안` 만 골라 볼 수 있습니다
- 어느 PC 에서, 언제, 어떤 프로그램이 발견되었는지 함께 남습니다
- 막지 못한 경우에는 그 사실과 이유까지 남습니다

직원 PC 쪽에도 `C:\ProgramData\HanilTimeGuard\timeguard.log` 에 같은 내용이 남습니다.
서버와 연결이 끊긴 동안 쌓인 기록은 다시 연결되면 서버로 올라갑니다.

## 껐다 켜기를 반복하면

허용 시간 밖에서 PC 를 켜면 작업을 저장할 유예(기본 120초)를 줍니다.
매번 같은 유예를 주면 껐다 켜기를 되풀이해 그 시간만큼씩 쓸 수 있으므로,
**다시 켤수록 유예가 절반씩 짧아집니다**(최소 15초). 몇 번째 시도인지도 서버에 기록됩니다.
허용 시간이 되면 이 기록은 지워집니다.

## 관리 화면

| 화면 | 하는 일 |
|---|---|
| **PC 목록** | 각 PC 의 현재 상태, 접속 여부, 마지막 연결 시각 |
| **PC 상세** | 그 PC 전용 시간표, 즉시 연장·중지, 최근 기록 |
| **연장 요청** | 직원 요청 승인·거절. 요청보다 적게 줄 수도 있음 |
| **기본 시간표** | 전용 시간표를 쓰지 않는 모든 PC 에 적용 |
| **기록** | 언제 어느 PC 가 꺼졌는지 전체 조회 |
| **새 PC 승인** | 새로 설치된 PC 를 승인·거절. 승인 전에는 정책이 내려가지 않음 |
| **설정** | 직원 PC 설치 방법, 연결 끊김 판단 기준, 비밀번호 |

화면 모습은 `docs/` 폴더의 캡처 이미지를 보십시오.

## 직원이 보는 모습

작업 표시줄에 TimeGuard 아이콘이 생깁니다. 마우스를 올리면 남은 시간이 보이고,
클릭하면 자세한 안내가 뜹니다.

- 종료 **10분 / 5분 / 1분 전** 알림
- 마지막 **60초 카운트다운 창** (화면 최상위, 닫을 수 없음)
- 시간이 다 되면 전원 차단

카운트다운 창은 **포커스를 뺏지 않으므로** 그 동안에도 작업을 저장할 수 있습니다.

### 연장 요청

트레이 아이콘 오른쪽 클릭 → **사용 시간 연장 요청**

창이 뜨면 두 가지를 입력합니다.

| 항목 | 내용 |
|---|---|
| 필요한 시간 | 30분 / 1시간 / 2시간 / 3시간 / 4시간 중 선택 |
| **사유** | 관리자가 보고 판단합니다. **비워 두면 보내지지 않습니다** |

보내면 관리자 화면 [연장 요청] 에 **요청자, 요청 시간, 사유**가 함께 뜹니다.
관리자는 승인하거나 거절할 수 있고, 요청한 것보다 적게 줄 수도 있습니다.
거절할 때는 사유를 적어 보낼 수 있습니다.

승인이나 거절 결과는 직원 화면에 알림으로 뜨고, 승인되면 곧바로 반영됩니다.

## 시간대 표기법

| 입력 | 뜻 |
|---|---|
| `09:00-18:00` | 하루 한 구간 |
| `09:00-12:00, 13:00-18:00` | 점심시간 제외 |
| `22:00-06:00` | 자정을 넘기는 야간 근무 |
| `없음` | 그 요일은 사용 불가 |
| `종일` | 24시간 허용 |

|---|---|
| **관리 화면 접근 제한** | 지정한 PC 에서만 관리 화면이 열립니다. 직원 PC 에서는 로그인 화면조차 나오지 않습니다. 서버 [설정] 에서 버튼 한 번으로 설정합니다 |
| **로그인 대입 차단** | 다섯 번 틀리면 그 위치에서 15분간 로그인할 수 없습니다 |
| **통신 암호화** | 설치할 때 인증서를 자동으로 만들어 HTTPS 로 통신합니다. 관리자가 인증서를 다룰 일이 없습니다 |
| **가짜 서버 차단** | 클라이언트는 처음 등록할 때 본 서버 인증서를 기억하고, 달라지면 연결을 끊습니다 |
| **서비스 보호** | 서비스를 함부로 멈출 수 없게 권한을 좁힙니다. 제거 스크립트가 알아서 되돌립니다 |
| **프로그램 보호** | 일반 사용자는 설치 폴더의 파일을 지우거나 바꿀 수 없습니다 |
| **설정 파일 보호** | 일반 사용자는 읽기만 가능하고, 고쳐도 서버 정책으로 되돌아갑니다 |
| **변조 감지** | 서비스를 멈추면 서버 화면에 "연결 끊김" 으로 남아 관리자가 알 수 있습니다 |
| **원격 접속 차단** | 허용 시간이 아닐 때 원격 데스크톱으로 들어올 수 없게 합니다 |
| **원격 제어 프로그램 차단** | 팀뷰어·AnyDesk 등을 멈춥니다. 서비스로 상주하는 것도 함께 멈춥니다 |
| **시도 기록** | 원격으로 들어오려 한 시도를 모두 기록에 남깁니다. 막지 못한 경우에도 남습니다 |
| **관리자 권한 감지** | 직원이 관리자 권한으로 로그인한 PC 를 찾아 화면에 알립니다 |

### 가장 중요한 한 가지 — 직원 계정 권한

위의 보호들은 **직원 계정이 일반 사용자일 때** 제대로 듣습니다.
직원 계정에 관리자 권한이 있으면 서비스를 멈춰 전부 무력화할 수 있고,
**계정 잠금 조치도 적용되지 않습니다**(관리자 계정을 잠그면 PC 를 되돌릴 수
없게 되므로 일부러 그렇게 만들었습니다).

그래서 **어느 PC 가 아직 위험한지 서버가 알려 줍니다.**

- **PC 목록** 화면 위쪽에 "N 대의 PC 에서 직원이 관리자 권한으로 로그인" 이라고 뜹니다
- 해당 PC 줄에 **관리자 권한** 표시가 붙습니다
- 처음 발견되면 기록에도 남습니다
- 권한을 낮추면 다음 연락 때 표시가 사라집니다

낮추는 방법은 **[`docs/직원계정_권한낮추기.md`](docs/직원계정_권한낮추기.md)** 에
비전문가도 따라 할 수 있게 정리해 두었습니다. PC 한 대에 10분이면 됩니다.

> 그 문서의 **2단계(관리자 계정 먼저 확보)** 를 건너뛰지 마십시오.
> 건너뛰면 그 PC 에서 아무것도 못 하게 됩니다.

## 안전장치

시간 제한 프로그램이 오작동해 업무 PC 가 꺼지면 피해가 큽니다.
**의심스러우면 차단하지 않는 쪽**으로 만들었습니다.

| 상황 | 동작 |
|---|---|
| 설정 파일이 없거나 손상됨 | 감시 꺼짐 상태로 동작 (절대 켜진 채 넘어가지 않음) |
| 서버 정책을 한 번도 못 받음 | 제한하지 않음 |
| 서버 연결 끊김 | **마지막으로 받은 시간표를 계속 적용** |
| 감시 루프 오류 | 기록 후 다음 초에 계속 (서비스는 죽지 않음) |
| 전원 차단 실패 | 기록 후 30초 뒤 재시도 |
| 조치 실행 직후 | 5분간 중복 실행 안 함 |

**허용 시간대 밖에서 PC 를 켠 경우**에는 곧바로 끄지 않고 기본 120초의 유예를 줍니다.
반대로 사용 중에 시간이 끝난 경우에는 이미 10분 전부터 경고했으므로 유예 없이 실행합니다.

## 파일 위치

**관리 서버**
```
C:\Program Files\HanilTimeGuardServer\    프로그램
C:\ProgramData\HanilTimeGuardServer\
    timeguard.db                           모든 설정과 기록 (이 파일만 백업하면 됩니다)
    최초설정정보.txt                        첫 로그인 정보 (확인 후 삭제)
```

**직원 PC**
```
C:\Program Files\HanilTimeGuard\          프로그램
C:\ProgramData\HanilTimeGuard\
    config.json                            현재 적용 중인 설정 (일반 사용자는 읽기 전용)
    server.json                            서버 주소와 장비 토큰
    policy-cache.json                      마지막으로 받은 시간표 (연결이 끊겨도 이걸 씁니다)
    timeguard.log                          기록
```

서버 모드에서는 `config.json` 을 손으로 고쳐도 **서비스가 서버 정책으로 되돌립니다.**

## 서버 없이 쓰기

PC 한두 대만 관리한다면 서버 없이도 씁니다. 이 경우 `TimeGuard.Admin.exe` 를 실행해
메뉴에서 직접 시간표를 설정합니다. 서버에 등록하지 않으면 자동으로 이 모드입니다.

이미 등록한 PC 를 떼어 내려면:

```powershell
TimeGuard.Admin.exe unenroll
```

## 명령줄

```powershell
TimeGuard.Admin.exe status                                   # 현재 상태
TimeGuard.Admin.exe unenroll                                 # 단독 모드로
TimeGuard.Admin.exe log 50                                   # 기록 보기
TimeGuard.Admin.exe unlock-accounts                          # 잠긴 Windows 계정 풀기

# 서버 주소를 직접 지정해야 할 때만 (보통은 설치 후 승인만 하면 됩니다)
TimeGuard.Admin.exe enroll --server <주소> --key <등록키>

# 단독 모드에서만 동작합니다 (서버 모드에서는 서버가 관리)
TimeGuard.Admin.exe set-window 평일 09:00-18:00 -p 비밀번호
TimeGuard.Admin.exe extend 30 -p 비밀번호
TimeGuard.Admin.exe enable -p 비밀번호
```

## 개발자용

### 빌드

```bash
./build/publish.sh          # 직원 PC 용 + 관리 서버 배포본
./build/publish.sh --all    # 단독 실행 파일까지 만들고 zip 으로 묶음
```

### 테스트

```bash
dotnet test
```

- **Core 58개** — 스케줄 판정, 설정 저장, 비밀번호 해시
- **서버 55개** — 실제 HTTP 파이프라인을 통과시키는 통합 테스트.
  등록·인증·정책 배포·연장 승인·쿼리 번역·클라이언트 연동까지 포함

스케줄 판정은 부작용 없는 순수 계산으로 분리해 두어 Windows 없이도 전부 검증됩니다.
서버는 Linux 에서 그대로 띄워 확인할 수 있습니다.

```bash
dotnet run --project src/TimeGuard.Server    # http://localhost:8080
```

### UI 구현에 관하여

직원 PC 쪽 경고 창과 트레이 아이콘은 WinForms/WPF 없이 **Win32 API 직접 호출**로
만들었습니다. 배포본에 Windows Desktop 런타임이 필요 없어 용량이 줄고,
Linux/CI 환경에서도 Windows 용 바이너리를 빌드할 수 있습니다.
