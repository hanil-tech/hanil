# 📦 한일 포털 대용량 파일·폴더 (bigfile)

포털에서 **큰 파일(파일 하나 50GB 까지)과 폴더째**를 올리고 받는 화면입니다. **파일을 잃어버리지 않게** 만들었습니다.
**설치할 것이 없습니다** — ActiveX·플러그인·별도 프로그램 없이 크롬·엣지·웨일, 폰 브라우저와 한일 포털 앱에서 그대로 됩니다
(HTML5 파일 읽기 + 보통 HTTP 만 씀).

| 할 수 있는 것 | 어떻게 |
|---|---|
| **폴더째 올리기** | 폴더를 끌어다 놓거나 [폴더 고르기] — 하위 폴더 구조 그대로, 끌어다 놓으면 빈 폴더까지 |
| **빠진 파일 0** | 올리기 전에 **목록표**(모든 파일의 경로·크기·빈 폴더)를 서버에 먼저 보냄 → 다 올린 뒤 목록표와 맞춰 「파일 n개 중 n개」를 확인, 빠진 것은 저절로 다시 |
| **폴더째 받기** | 크롬·엣지(https): 받을 곳을 고르면 하위 폴더까지 그대로 만들며 받음 → 끝나면 **받은 폴더를 다시 세어** 목록표와 맞춰 봄 · 그 밖(http·폰 앱): **ZIP** 으로 |
| **크기 제한 없음** | 올리기·받기 모두 메모리에 모으지 않고 흘려 보냄 — 받기(고른 자리)·보통 내려받기·ZIP 모두 크기 제한 없음, 끊기면 이어 받음 |
| 큰 파일 올리기 | 8MB 조각을 3개씩 함께 · 조각마다 CRC32 · 진행률·속도·남은 시간 |
| **끊겨도 이어 올리기** | 망이 끊기거나 창을 닫거나 서버를 다시 켜도, 같은 파일·폴더를 다시 고르면 이미 올라간 파일은 건너뛰고 받아 둔 조각 다음부터 |
| **그림으로 보기** | 「내 PC → 포털 서버」 막대 + 지도(파일 하나는 조각마다, 폴더는 파일마다 한 칸: 기다림·보내는 중·보냄·다시·검사 통과·틀림) |
| **끝난 뒤 검사** | 서버가 디스크에서 다시 읽어 **파일 수·빠진 파일·크기·조각별 CRC32·전체 CRC32(·SHA-256)** 를 내 PC 값과 하나하나 맞춰 표로 |
| **불합격이면 다시 보냄** | 틀린 조각·빠진 파일만 저절로 다시 보내고 다시 검사(3번까지) · 받을 때도 틀린 조각만 다시 받음 |
| **맞춰 보기** | ZIP 으로 받아 푼 폴더·브라우저로 받은 파일을 고르면 서버 목록표와 하나하나 비교 → 없는 파일·크기 다른 파일·내용 다른 파일을 이름째 알려 줌(파일은 내 PC 밖으로 안 나감) |
| 서버 검사 | 목록의 [검사] — 서버의 파일·폴더가 올릴 때 그대로인지 언제든 다시 확인. 불합격이면 올린 사람이 [다시 올려 고치기](같은 것을 고르면 틀린 것만) |
| 다시 받기 | 같은 자리에 폴더를 다시 받으면 이미 똑같이 있는 파일(크기·CRC 확인)은 건너뜀 — 끊겼다가 이어 받기 |
| 사내 공개 · 링크 | [사내 공개] 로그인한 직원 누구나 · [링크] 로그인 없이(기한 1~30일·횟수 제한) — 폴더는 ZIP 으로 |
| 관리자 | 「전체(관리자)」 칸에서 모든 사람의 것을 보고 지움 |

### 받는 법 — 어디서 무엇이 되나

| 어디서 | 파일 | 폴더 |
|---|---|---|
| 크롬·엣지를 **https**(또는 localhost)로 | 저장할 곳을 고르면 조각마다 검사하며 바로 씀 | 받을 곳을 고르면 하위 폴더까지 그대로 · 다시 세어 검사 |
| 그 밖(http 주소·다른 브라우저) | 보통 내려받기 → 받은 뒤 [맞춰 보기] | **ZIP** → 풀고 나서 [맞춰 보기] |
| 한일 포털 앱(폰) | 보통 내려받기(앱의 내려받기) | ZIP |

모두 **크기 제한 없음**, 끊기면 이어 받습니다(Range). 목록의 「브라우저로 바로 받기」·「ZIP 으로 받기」는 언제든 됩니다.
⚠ 폴더 **올리기**는 PC 에서만 됩니다(폰 브라우저·앱은 폴더를 고를 수 없음 — 파일은 됨).

### ZIP

- 압축 없이 묶습니다(도면·사진은 압축해도 거의 안 줄고, 압축 없이 묶어야 길이를 미리 알아 **이어 받기**가 됨).
- 4GB 넘는 파일·묶음은 ZIP64 · 이름은 UTF-8(윈도 탐색기·반디집·7-Zip 에서 한글이 안 깨짐) · 빈 폴더도 들어감.
- 파일마다 CRC32 가 들어 있어 푸는 프로그램이 깨진 파일을 알려 줍니다. 풀고 나서 [맞춰 보기]를 하면 빠진 파일까지 확인됩니다.

### 시험한 것

- 점검 도구 `test/api-check.js` **69가지** 통과(폴더 목록표·빠진 파일 찾기·이어 가기·ZIP(파이썬이 열어 내용 확인)·ZIP 이어 받기·권한·링크·고치기 …).
- 실제 크로미움으로 폴더(30개 파일·213MB·한글·띄어쓰기·하위 3단·0바이트·딱 8MB 파일):
  - 올리다 멈춤 → 서버 다시 켬 → 같은 폴더 고름 → 이미 올라간 파일은 건너뛰고 이어 감 → 검사 합격(30/30)
  - 다 보낸 직후 서버 디스크의 두 파일을 망가뜨림 → 그 두 조각만 저절로 다시 보내 합격, 서버 파일 = 원본
  - 고른 폴더에 받기 → 30개 SHA-256 모두 원본과 같음 · 같은 자리에 다시 받기 → 30개 모두 「이미 있음」으로 건너뜀
  - ZIP 받기 → 풀면 30개 모두 원본과 같음 · 푼 폴더에서 1개 지우고 1개 크기 바꾸고 1개 2바이트 바꿈 → [맞춰 보기]가 셋 다 이름째 찾음
  - 서버 디스크 고장 → [검사]가 찾음 → [다시 올려 고치기] → 망가진 조각 1개만 보내 합격
- 4.5GB 파일이 든 폴더의 ZIP64 → 파이썬 zipfile 로 열어 검사 통과.
- 끌어다 놓기(빈 폴더 포함)는 시험 도구로 흉내 낼 수 없어 **사람이 한 번 확인**해 주세요(빈 폴더는 API·ZIP 점검에서 시험함).

## 포털에 넣기 (포털 담당)

**받기: [hanil-bigfile-portal.zip](https://github.com/hanil-tech/hanil/raw/HEAD/release/hanil-bigfile-portal.zip)** (안에 `설치안내.txt` · `주의사항.txt` · 두 파일 · 이 README). 고친 뒤 다시 묶기: `bigfile/build.sh`

1. `portal/bigfile-route.js` 와 `portal/bigfile.html` 을 포털 폴더(`server.js` 옆)에 둡니다.
2. `server.js` 에서 세션(express-session)이 붙은 뒤(다른 `require('./…')(app, …)` 들 사이) **한 줄**:
   ```js
   require('./bigfile-route')(app);
   ```
3. 포털을 다시 띄웁니다. 메뉴에 `/bigfile` 링크를 달면 됩니다(→ `/bigfile/view`, 공통 조각이 안 끼는 주소).

더 깔 것(npm 꾸러미)이 없습니다 — Node 기본 기능만 씁니다.

### ⚠ 앞에 nginx(또는 다른 프록시)가 있으면

조각(8MB)이 통과하게 늘려 주세요. 기본값(1MB)이면 화면에 「서버(nginx 등)가 조각을 너무 크다고 막았습니다」가 나옵니다.

```nginx
client_max_body_size 16m;
proxy_request_buffering off;   # 조각을 디스크에 한 번 더 쓰지 않게
proxy_buffering off;           # 받을 때 큰 파일을 nginx 가 쌓아 두지 않게
proxy_read_timeout 600s;
```

### 로그인한 사람을 알아보는 법

`req.session.user` 의 `id`(없으면 `user_id`·`username`·`name`)로 주인을 정하고,
`is_admin`·`isAdmin`·`admin`·`role === 'admin'` 중 하나라도 있으면 관리자로 봅니다.
포털 세션 모양이 다르면 직접 넘깁니다:

```js
require('./bigfile-route')(app, {
  user: (req) => req.session.user && { id: String(req.session.user.no), name: req.session.user.nm, admin: req.session.user.lv >= 9 },
});
```

### 포털 색에 맞추기

화면은 포털 안에 붙이기 좋게 단순하게(흰 바탕·회색 선·강조색 하나·글자 단추) 만들었습니다.
색은 `bigfile.html` 맨 위 `:root{…}` 몇 줄만 바꾸면 됩니다 — `--acc`(강조색: 단추·진행 막대), `--head`(제목줄 바탕), `--line`(선).
포털 메뉴에서 새 창 대신 포털 화면 안(iframe)에 넣어도 됩니다: `<iframe src="/bigfile/view" style="width:100%;height:900px;border:0"></iframe>`

### 설정 (모두 고를 수 있음)

```js
require('./bigfile-route')(app, {
  dir: 'D:/portal-files',   // 파일 둘 곳 (기본: server.js 옆 bigfile-store/, 또는 환경 변수 BIGFILE_DIR)
  maxGB: 50,                // 파일 하나 최대
  quotaGB: 0,               // 한 사람 합계(0 = 제한 없음)
  keepFreeGB: 5,            // 서버 디스크를 이만큼은 남겨 둠 — 모자라면 올리기를 시작하지 않음
  partialDays: 7,           // 다 못 올린 것은 마지막 조각 뒤 7일에 지움
  keepDays: 0,              // 다 올린 것을 n일 뒤 지움(0 = 안 지움)
  shareDaysMax: 30,         // 링크 기한 최대
  chunkMB: 8,               // 조각 크기(nginx client_max_body_size 보다 작게)
  parallel: 3,              // 한꺼번에 몇 조각씩 보내나(폴더는 파일 여럿이 이것을 나눠 씀)
  maxEntries: 200000,       // 폴더 하나에 파일·폴더 수
});
```

## ⚠ 주의사항

전체는 [주의사항.txt](주의사항.txt)(묶음에도 들어 있음 — Ⅰ부는 직원에게 그대로 전달). 꼭 지킬 것만:

- **포털을 하나만 띄웁니다** — 올리는 중인 파일 정보를 메모리에 들고 있어 pm2 cluster·여러 대로 나누면 조각이 엇갈립니다.
- **Node.js 18.15 이상** — 낮으면 디스크 남은 자리를 못 읽어 가득 찰 때까지 막지 못합니다.
- **nginx 가 있으면 `client_max_body_size 16m`** — 없으면 큰 파일이 안 올라갑니다.
- **처음 켜고 확인** — 오른쪽 위에 자기 이름, 관리자에게 「전체(관리자)」 칸. 아니면 `user` 설정을 넣습니다.
- **[링크]는 가진 사람 누구나 받습니다** — 기한·횟수를 정하고, 다 받으면 끊습니다. 바깥에 열 때는 https 로.
- **`bigfile-store/` 를 손으로 고치지 않습니다** — 지우기는 화면의 [삭제], 백업은 폴더째 복사.
- **경로가 아주 긴 폴더** — 윈도는 경로 260자를 넘으면 풀거나 받지 못할 수 있습니다. 받을 곳을 `D:\받음` 처럼 짧게.
- 바이러스 검사는 하지 않습니다 · 보관 창고가 아니라 주고받는 곳입니다(원본은 따로).

## 저장 모양

```
bigfile-store/
  data/<열쇠>.bin    파일 내용 (디스크에는 원래 이름을 쓰지 않음 — 이상한 이름으로 폴더를 벗어날 수 없음)
  meta/<열쇠>.json   이름·크기·주인·받은 조각·조각 CRC32·공유 링크·받은 횟수 (폴더 안 파일은 폴더 열쇠·경로도)
  groups/<열쇠>.json 폴더의 목록표(경로·크기·빈 폴더) · 공유 링크·검사 결과
```

- DB 를 쓰지 않습니다. 백업은 이 폴더를 통째로 복사하면 됩니다.
- 받을 때는 늘 「내려받기」로 내줍니다(`application/octet-stream` + `nosniff`) — 올린 HTML 이 포털 안에서 열려 로그인을 훔치는 일이 없게.
- 남의 비공개 파일 주소를 알아도 404 입니다(주인·관리자·사내 공개만).

## 주소

| 주소 | 하는 일 |
|---|---|
| `GET /bigfile` · `/bigfile/view` | 화면 |
| `GET /bigfile/api/info` · `/list[?all=1]` | 내 정보·한도 · 목록 |
| `PUT /bigfile/api/group` (몸통 `{name, entries:[{p,s,lm}\|{p,d:1}], gid?}`) | 폴더 목록표 — 같은 이름을 올리다 말았으면 이어 감(이미 온 파일은 그대로). `gid` 는 고치기(서버 파일은 안 지움) |
| `GET /bigfile/api/group/<폴더>[?crcs=1]` · `POST …/gdone/<폴더>` · `DELETE …/group/<폴더>` | 목록표·파일마다 상태·CRC · 다 올림(빠진 파일이 있으면 409 + 경로) · 지우기 |
| `POST·GET /bigfile/api/gverify/<폴더>[?again=1]` | 폴더 검사(서버 디스크 다시 읽기) — 빠진 파일·틀린 파일 |
| `GET /bigfile/api/group/<폴더>/zip` | 폴더째 ZIP (Range 됨) |
| `POST /bigfile/api/init?name=&size=&lm=` (폴더 안은 `?g=<폴더>&p=<경로>`) | 올리기 시작(같은 파일을 올리다 말았으면 그것을 이어 감) |
| `PUT /bigfile/api/chunk/<열쇠>/<번호>` | 조각 하나 (머리 `X-Crc32`) |
| `POST /bigfile/api/done/<열쇠>` | 다 보냄 — 빠진 조각·크기 확인 |
| `GET /bigfile/api/file/<열쇠>/dl` | 받기 (Range 됨) |
| `POST /bigfile/api/verify/<열쇠>[?again=1]` · `GET …/verify/<열쇠>` | 서버 검사 시작 · 진행(읽은 바이트)·결과 |
| `GET /bigfile/api/crcs/<열쇠>` | 조각별 CRC32 (받는 쪽이 맞춰 봄) |
| `POST /bigfile/api/reopen/<열쇠>?chunks=3,17` (또는 `all`) | 틀린 조각만 「안 받음」으로 되돌림(올린 사람만) → 다시 보낸 뒤 done·검사 |
| `POST /bigfile/api/pub/<열쇠>?on=1` (폴더는 `/pub/g/<폴더>`) · `DELETE /bigfile/api/file/<열쇠>` | 사내 공개 · 지우기 |
| `POST /bigfile/api/share/<열쇠>?days=&max=` (폴더는 `/share/g/<폴더>`) · `DELETE …/share/<열쇠>/<링크>` | 링크 만들기 · 끊기 |
| `GET /bigfile/s/<링크>` · `/bigfile/s/<링크>/dl` | 바깥 사람 받기 화면(폴더는 파일 목록) · 받기(폴더는 ZIP) (로그인 없음) |
