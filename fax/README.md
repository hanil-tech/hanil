# 📠 팩스 — CimFAX ↔ 한일 포털

CimFAX 팩스 서버와 포털을 잇는 포털 조각입니다. **받은 팩스**는 포털에 자동으로 올리고, 포털에서 **팩스를 보냅니다**.

```
받기:   CimFAX 장비 → FaxBox(자동 내보내기, PDF) → 공유 폴더 → fax-route.js (15초마다) → /fax 화면 · 알림
보내기: /fax 「✉ 팩스 보내기」 → PDF → 팩스 TIFF(Ghostscript) → cimfax-client.js → 장비 TCP 3002 → 전화선
```

분석 근거는 [`docs/CimFAX_포털연동_분석.md`](../docs/CimFAX_포털연동_분석.md) 에 있습니다.
- 받기: 5.1.1 항목. FaxBox 5022E 를 Ghidra 로 디컴파일해서 자동 내보내기가 실제로 동작하는 것을 확인했습니다.
- 보내기: 10장. CimFAX 공식 앱 FaxGo 를 디컴파일해서 로그인 계산, 1088 바이트 작업 머리, 1200 바이트 조각 전송, 상태 조회를 그대로 옮겼습니다.

| 파일 | 내용 |
|---|---|
| `portal/fax-route.js` | 포털에 넣는 조각. 받기(폴더 감시), 보내기(대기열·상태), API, 화면 연결 |
| `portal/fax-page.html` | `/fax` 화면. 받은 팩스, 보낸 팩스, 보내기 창. PC 와 폰 모두 지원 |
| `portal/cimfax-client.js` | CimFAX 장비 통신. 로그인, 보내기, 상태, PDF→팩스 TIFF |
| `portal/cimfax-check.js` | 현장 점검 도구. 로그인, 시험 팩스, 상태 |
| `portal/설치안내.txt` | 설치 순서. FaxBox 설정 → 포털에 넣기 → 보내기 설정 |
| `test/` | 가짜 포털, 가짜 내보내기 폴더, **가짜 CimFAX 장비**로 하는 점검 (`npm install && npm test`, Ghostscript 필요) |

## 점검 결과
- 받기 `npm run receive` → ✅ 33 · ❌ 0
- 보내기 `npm run send` → ✅ 24 · ❌ 0
  - 로그인 해시, 1088 바이트 머리(번호·쪽수·시각), 1200 바이트 조각 전송, 작업번호, 상태 조회
  - 여러 곳으로 보내기, 실패와 다시 보내기, 시험 모드, 권한
- 브라우저(Chromium): PC 와 폰 크기 모두 보내기 창 → 장비 접수까지 오류 없음

## 아직 현장에서 확인할 것 (보내기)
가짜 장비는 FaxGo 의 동작을 따라 만들었습니다. 실제 장비에서는 `cimfax-check.js` 로 다음을 한 번 확인해야 합니다.
1. 로그인
2. 시험 팩스 한 장 (받은 쪽 종이 화질 확인)
3. `--status` 로 장비 상태 코드의 뜻 (대기, 성공, 실패 값). 확인 전까지 화면에는 코드 숫자를 그대로 보여 줍니다.
